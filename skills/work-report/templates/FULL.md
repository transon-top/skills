# full 模式模板

大类映射、大类排序、聚合规则见 SKILL.md「分类提交」节，本文件定义叙述要求与输出骨架。面向技术领导。

## 叙述要求

每个功能域包含：

- **背景**：此阶段该功能域要解决的问题或整体目标（1-2 句）。体现业务意图或问题根因，不描述技术实现。
  - 素材优先级（默认）：ticket 主线 → merge 分支名（谁做的）→ commit messages；已查阅 MR/PR 时见 `../references/mr-pr.md`「数据利用」节
  - 协作信息（已查阅 MR/PR 时）：评审人 + 合并人可融入背景注记（如「由 X 评审、Y 合并」）
- **开发明细**：逐条叙述，串联相关提交为连贯描述。每条是一段完整的话，说明做了什么、为什么做，而非提交信息的简单翻译。

## 输出格式

功能域按 SKILL.md「分类提交」节大类排序，同大类内按提交数量降序排列。只输出有提交的大类。

```markdown
# 工作汇报 (<start-date> ~ <end-date>)

**分支**: <branch> | **提交数**: <count> | **作者**: <authors> [| **MR/PR数**: <count>] | **口径**: 交付日（已查阅 MR/PR 时以平台 merged_at 为准）

## 新功能开发

### <功能域一>

**背景**: <此阶段该功能域的整体目标或要解决的问题>

**开发明细**:
- <完整叙述，串联该功能域下的相关提交，说明做了什么、为什么做>
- ...

### <功能域二>

**背景**: ...

**开发明细**:
- ...

## 问题修复

### <功能域三>

**背景**: <问题现象与根因>

**开发明细**:
- ...
```

## 约束

- 功能域名称保持稳定：同一功能域在多个提交中出现时合并为一节，不重复拆开
- 同一 ticket 的 commits 聚合在一节内叙述，不拆散
- 跨提交的关联逻辑串联为连贯叙述，而非孤立罗列
