# 合并收口

> 进入：验收已定——issue 评论含「人工验收通过，准予合并」（「就绪加载」匹配到），或留档场景用户意图直入（回显确认即视为验收）。合并 → 交付评论 → 清理 → 切回 main。全动作类，走确认门。

## 合并（确认后执行）

- 确认清单：合并命令 + 合并方式（squash / merge，默认按仓库惯例，用户可改）+ 影响（合并后 issue 自动 close 与否、远程分支是否平台自动删）
- 执行：GitHub `gh pr merge` / GitLab `glab mr merge`，成功以平台侧为准（合并请求状态变 merged），不以退出码为准
- **失败** → 分析冲突原因、列出解决方案与下一步行为清单（以完成最终任务为导向：回「明确需求」重审 / 本地解决冲突推回 / 换合并方式），用户定夺，不自动 rebase、不自动重试

## 交付评论

- 留档场景必发；其他场景仅当存在代码仓库外的配合动作才发
- 内容按 `templates/comment.template.md`「交付评论」型：合并请求链接、标题与状态、变更清单、验证结果、代码仓库外配合动作（若有，提醒用户跟进）
- 评论类，走确认门全文预览

## 清理

- 合并成功 → 删本地验证分支：`git branch -D <验证分支>`
- 远程分支：平台合并通常自动删；仍存在则显式删（已自动删则跳过）
- 切回工作分支：`git checkout main` + pull

完成：合并已落平台（merged），交付评论已发（按场景），本地验证分支与远程残余分支已清，停在 main；出口「收尾」
